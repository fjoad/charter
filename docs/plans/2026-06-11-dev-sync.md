# v0.8.1 — dev-sync: staleness fixed structurally

**Status:** ✅ Complete (2026-06-11) — 104/104 tests pass, ready to merge.
**Branch:** `feat/dev-sync`

## Why

The installed plugin is perpetually behind the source repo for a dev who hacks on Charter daily (observed twice this arc: v0.1.0-installed/v0.3.0-source, then v0.3.0-installed/v0.6.0-source — the root cause behind sibling sessions reinventing shipped features). Staleness is a *consequence of the finish ritual*: ship a version, never refresh your own install. Fix the ritual, plus a belt-and-suspenders nudge.

## Changes

1. **`scripts/dev-sync.sh`** — one command wrapping the two supported CLI calls (`claude plugin marketplace update` + `claude plugin update`), with a pushed-state check first (marketplace pulls from GitHub; syncing unpushed work is a no-op). No JSON surgery — that path stays forbidden.
2. **Finish ritual step** (Charter's own `.claude/rules/workflow.md` only — user projects don't develop Charter): after pushing a release tag, run dev-sync.
3. **Opt-in staleness nudge in the session-start hook:** if `CHARTER_DEV_SOURCE` (env) or `~/.config/charter/dev-source` (file containing a path) points at a source repo, compare the plugin's own `plugin.json` version against the source's; if they differ, inject ONE orient line saying so. Zero cost when in sync; fail-silent on any error. Tests hermetic via env override.
4. AGENTS.md § Iterating updated; structural test assertions; ADR; bump 0.8.1.

## Non-goals

- Auto-running dev-sync from the hook (hooks should never mutate plugin state)
- Network version checks in the hook (slow, flaky; local source compare only)
